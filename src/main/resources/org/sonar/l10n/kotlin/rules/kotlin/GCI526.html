With Bluetooth Low Energy (BLE), the connection priority controls the frequency of connection events between the GATT client (master) and the GATT server (slave). Higher priority means more frequent events and significantly more battery consumption.

When calling BluetoothGatt.requestConnectionPriority(int), always use CONNECTION_PRIORITY_LOW_POWER (value 2) unless low latency is strictly required. Using CONNECTION_PRIORITY_BALANCED or CONNECTION_PRIORITY_HIGH increases radio wake-ups and drains the battery faster.

Noncompliant Code Example

// Noncompliant — high priority increases radio activity and battery drain
bluetoothGatt.requestConnectionPriority(BluetoothGatt.CONNECTION_PRIORITY_HIGH)

// Noncompliant — balanced is better than high but still not optimal
bluetoothGatt.requestConnectionPriority(BluetoothGatt.CONNECTION_PRIORITY_BALANCED)

Compliant Solution

// Compliant — low power minimizes radio wake-ups
bluetoothGatt.requestConnectionPriority(BluetoothGatt.CONNECTION_PRIORITY_LOW_POWER)
