The 3-argument form of SensorManager.registerListener() delivers sensor events as soon as possible, waking the Application Processor (AP) on every event. The 4-argument form adds a maxReportLatencyUs parameter: events are buffered in the sensor hardware FIFO for up to that many microseconds before being flushed together. This lets the AP stay in a low-power state between flushes, reducing power consumption.

Always pass a positive maxReportLatencyUs value. Passing 0 disables buffering and is equivalent to the 3-argument form.

Noncompliant Code Example

// No latency — AP woken on every event
sensorManager.registerListener(listener, sensor, SensorManager.SENSOR_DELAY_NORMAL)         // Noncompliant

// Latency 0 — buffering disabled
sensorManager.registerListener(listener, sensor, SensorManager.SENSOR_DELAY_NORMAL, 0)      // Noncompliant

Compliant Solution

// 200 ms latency — AP can idle between batches
sensorManager.registerListener(listener, sensor, SensorManager.SENSOR_DELAY_NORMAL, 200_000) // Compliant
