Thread.sleep() blocks the current thread synchronously, wasting CPU cycles and battery. On Android, blocking the main thread freezes the UI and creates ANR (Application Not Responding) errors. Even on background threads, blocking is inefficient and prevents responsive task scheduling.

Noncompliant Code Example

fun delayedTask() {
    Thread.sleep(1000) // Noncompliant — blocks thread
    doWork()
}

fun pollWithDelay() {
    for (i in 1..10) {
        Thread.sleep(100) // Noncompliant — especially in loops
        checkStatus()
    }
}

Compliant Solution

// Use coroutines and delay()
suspend fun delayedTask() {
    delay(1000) // Non-blocking, suspends only this coroutine
    doWork()
}

// Or use Handler/post-delayed on Android
Handler(Looper.getMainLooper()).postDelayed({
    doWork()
}, 1000)

// Or use ScheduledExecutorService
scheduler.schedule({ checkStatus() }, 100, TimeUnit.MILLISECONDS)

Why It Matters

  • Battery drain: Blocked threads consume CPU even while idle, draining battery
  • UI freezing: Blocking the main thread stops frame rendering, harming user experience
  • Resource waste: Threads are expensive OS resources; blocking them prevents efficient multiplexing
