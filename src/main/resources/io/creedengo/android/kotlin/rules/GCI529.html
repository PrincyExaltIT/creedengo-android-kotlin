Giving information to the end-user through notifications is an important aspect of a modern app. However, a notification does not necessarily need to be loud or vibrant to achieve its purpose — the default mode is enough.

Avoid calling setSound(), setVibrate(), or setVibrationPattern() with non-null arguments on a Notification.Builder or NotificationChannel. These trigger hardware actuators that consume extra energy. Passing null to these methods is compliant as it removes any previously set effect.

Noncompliant Code Example

// API 26+ — Notification.Builder
val builder = Notification.Builder(context, "channel-id")
builder.setVibrate(longArrayOf(1000, 1000, 1000)) // Noncompliant
builder.setSound(
    RingtoneManager.getDefaultUri(RingtoneManager.TYPE_NOTIFICATION),
    Notification.AUDIO_ATTRIBUTES_DEFAULT
) // Noncompliant

// API 31+ — NotificationChannel
val channel = NotificationChannel("channel-id", "My Channel", NotificationManager.IMPORTANCE_DEFAULT)
channel.setVibrationPattern(longArrayOf(1000, 1000, 1000)) // Noncompliant
channel.setSound(
    RingtoneManager.getDefaultUri(RingtoneManager.TYPE_NOTIFICATION),
    Notification.AUDIO_ATTRIBUTES_DEFAULT
) // Noncompliant

Compliant Solution

// Rely on the default notification behaviour — no extra hardware actuators
val builder = Notification.Builder(context, "channel-id")
// No setVibrate() or setSound() call

// Or explicitly remove vibration/sound by passing null
val channel = NotificationChannel("channel-id", "My Channel", NotificationManager.IMPORTANCE_DEFAULT)
channel.setVibrationPattern(null) // Compliant — removes vibration
channel.setSound(null, null)      // Compliant — removes sound
