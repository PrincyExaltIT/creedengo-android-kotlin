When requesting location updates, using LocationManager.getBestProvider() with a low-power Criteria lets the OS pick the least energy-intensive provider available. Skipping this and requesting updates directly on a fixed provider (e.g. GPS_PROVIDER) forces the most power-hungry source regardless of need.

Three escalating checks apply:

  1. If requestLocationUpdates is called without getBestProvider, flag it.
  2. If getBestProvider is used but Criteria.setPowerRequirement is never called, flag getBestProvider.
  3. If setPowerRequirement is called with a value other than POWER_LOW, flag the call.

Noncompliant Code Example

    lm.requestLocationUpdates(LocationManager.GPS_PROVIDER, 1000L, 1f, this)  // Case 1

Compliant Solution

    val criteria = Criteria()
    criteria.setPowerRequirement(Criteria.POWER_LOW)
    lm.requestLocationUpdates(lm.getBestProvider(criteria, true), 1000L, 1f, this)
