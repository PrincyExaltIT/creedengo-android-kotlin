Applications are strongly discouraged from using exact alarms unnecessarily as they reduce the OS's ability to minimize battery use (i.e. Doze Mode).

For most apps prior to API 19, setInexactRepeating() is preferable over setRepeating(). Android synchronizes multiple inexact repeating alarms and fires them at the same time, reducing battery drain.

After API 19, setExact() and setExactAndAllowWhileIdle() can significantly impact power use when the device is idle, so they should be used with care.

Noncompliant Code Example

val alarmManager = getSystemService(Context.ALARM_SERVICE) as AlarmManager

// Noncompliant — exact, prevents Doze Mode batching
alarmManager.setExact(AlarmManager.RTC_WAKEUP, triggerAtMillis, pendingIntent)

// Noncompliant — repeating exact alarm
alarmManager.setRepeating(AlarmManager.RTC_WAKEUP, triggerAtMillis, intervalMillis, pendingIntent)

// Noncompliant — exact alarm even while idle
alarmManager.setExactAndAllowWhileIdle(AlarmManager.RTC_WAKEUP, triggerAtMillis, pendingIntent)

Compliant Solution

val alarmManager = getSystemService(Context.ALARM_SERVICE) as AlarmManager

// Compliant — inexact, allows the OS to batch alarms and save battery
alarmManager.setInexactRepeating(
    AlarmManager.RTC_WAKEUP, triggerAtMillis, AlarmManager.INTERVAL_HOUR, pendingIntent
)

// Better alternative: use WorkManager for deferrable background work
val request = PeriodicWorkRequestBuilder<MyWorker>(1, TimeUnit.HOURS).build()
WorkManager.getInstance(context).enqueue(request)
