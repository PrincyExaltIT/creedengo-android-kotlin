Since Android 5.0 (API 21), the JobScheduler API lets the system batch and defer background work to a time that is optimal for battery life. Using AlarmManager scheduling methods or AbstractThreadedSyncAdapter directly bypasses this batching, causing the device to wake up more frequently and draining the battery faster.

Replace AlarmManager scheduling calls and sync adapter usage with JobScheduler (or the Jetpack WorkManager wrapper, which handles compatibility automatically).

Noncompliant Code Example

val alarmManager = getSystemService(Context.ALARM_SERVICE) as AlarmManager
alarmManager.setRepeating(                                          // Noncompliant
    AlarmManager.RTC_WAKEUP,
    System.currentTimeMillis(),
    10 * 60 * 1000L,
    pendingIntent
)
alarmManager.set(AlarmManager.RTC_WAKEUP, triggerAt, pendingIntent) // Noncompliant
alarmManager.setWindow(AlarmManager.RTC_WAKEUP, 0, 60_000L, pendingIntent) // Noncompliant

Compliant Solution

val scheduler = getSystemService(JobScheduler::class.java)
val info = JobInfo.Builder(JOB_ID, ComponentName(this, MyJobService::class.java))
    .setPeriodic(10 * 60 * 1000L)
    .setRequiredNetworkType(JobInfo.NETWORK_TYPE_ANY)
    .build()
scheduler.schedule(info)
